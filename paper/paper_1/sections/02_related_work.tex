\section{Related Work}
\label{sec:related}

ASK combines established ideas but assigns them a specific systems role: they
form a governance boundary before a persistent write. We distinguish memory
architectures, write policies, temporal stores, abstention mechanisms, and
evaluation instruments because similarity on one axis does not imply an
equivalent governance contract.

\paragraph{Persistent agent memory and write policies.}
MemGPT/Letta \citep{packer2023memgpt}, Mem0 \citep{chhikara2025mem0}, A-MEM
\citep{xu2025amem}, and RMM \citep{tan2025rmm} organize persistent memories and
expose add, update, merge, delete, or no-op behavior. Memory-R1
\citep{yan2025memoryr1} learns discrete memory-management actions by
reinforcement learning, while Generative Agents \citep{park2023generative}
uses an additive event stream with reflection and retrieval. These systems
establish that an agent memory requires a write policy. ASK contributes a
controller-independent audit and transition contract around such a policy. In
particular, generic \texttt{NOOP} is not automatically an ASK \abstain:
duplicate or irrelevant content may require no operation without uncertainty
about a proposed durable update.

\paragraph{Temporal conflict resolution, provenance, and lineage.}
Zep/Graphiti \citep{rasmussen2025zep} invalidates contradicted edges with
bi-temporal metadata, and TOKI \citep{wang2026toki} formalizes bitemporal
operators for persistent-memory conflict resolution. FadeMem
\citep{fademem2026} combines pairwise classification with decay and fusion,
while deterministic consolidation work \citep{reddy2026deterministic} motivates
transparent conflict policies. MemStrata \citep{yadav2026memstrata} targets
stale-fact errors through temporal validity at retrieval. These systems precede
ASK on temporal representation, retained history, or deterministic resolution.
ASK's narrower contribution is to bind a proposed write action to evidence,
validate its state consequence, and score action, state, lineage, and retrieval
separately.

\paragraph{Typed memory and provenance-bearing dialogue data.}
MemGuard \citep{ha2026memguard} assigns functional memory roles at write time,
and MemOS \citep{li2025memos} distinguishes memory levels. Typed memory is not a
novelty claim here. CareCallMem \citep{bae2022keep} provides long-term
conversation data and a memory-management task with updated information. WRIT
\citep{hendrickson2026writ} represents multi-session memory events with
introduction, update, retraction, persistence, previous values, and provenance.
These resources are relevant to naturalistic evaluation, but their labels and
publication status differ from direct ASK action gold. They are neighbors and
possible future adapters, not evidence included in our reported results.
PrefEval \citep{zhao2025prefeval} and PersonaMem
\citep{jiang2025personamem} further motivate evaluation of changing preferences
and user profiles, but neither supplies gold ASK actions for our runtime.

\paragraph{Direct diagnostics of memory updates.}
HaluMem \citep{halumem2025} separately evaluates extraction, update, and QA for
memory hallucination. STALE \citep{chao2026stale} probes whether an agent
recognizes obsolete memory at read time, and Supersede
\citep{patel2026supersede} studies the answer-level memory-update gap. The
MemPatch-Bench artifact \citep{zhu2026mempatch} evaluates post-admission
revision using operations, state maps, and evidence identifiers. MemOps
\citep{hao2026memops} also treats memory operation as an explicit evaluation
object. These are the closest conceptual neighbors to MGP-6. MGP-6 differs in
the exact three-way decision and single-slot post-transition targets, but it is
an evaluation instrument rather than the ASK framework.

\paragraph{Long-term and multi-principal evaluation.}
LongMemEval \citep{wu2025longmemeval} and LoCoMo
\citep{maharana2024locomo} evaluate long-term conversational memory through
answers. Memora \citep{uddin2026memora} penalizes obsolete-memory use, MemGym
\citep{xu2026memgym} reports memory-isolated scores across agentic regimes, and
GroupMemBench \citep{yang2026groupmembench} includes multi-party update and
abstention cases. GateMem \citep{ren2026gatemem} uses ``memory governance'' for
authorization across principals, which is a different control problem from
ASK's epistemic write decision. End-to-end benchmarks provide downstream
evidence, but without candidate-level write annotations they cannot identify
the gold ASK action for every mutation.

\paragraph{Selective prediction and belief change.}
The reject option \citep{chow1970reject,elyaniv2010selective,
geifman2017selective} and learning to defer \citep{madras2018defer,
mozannar2020defer} precede ASK's abstention mechanism. RSCB-MC
\citep{iscan2026rscbmc} applies abstention to retrieval or context injection,
whereas ASK applies it before a write. AGM belief revision
\citep{alchourron1985agm} is conceptual ancestry for preservation and revision;
we prove no AGM-postulate compliance. Parametric knowledge editing
\citep{meng2022rome,meng2023memit} determines how to change model parameters
after an edit has been selected. ASK instead governs whether an external-memory
change should be committed.

The contribution boundary follows from these precedents. ASK does not own its
action vocabulary or any individual representation mechanism. It specifies an
integrated write-time contract in which policy proposal, storage mutation,
lineage, audit reconstruction, retrieval, and answer evaluation remain
separable. The experiments test portions of that contract under explicit scope
limits.
