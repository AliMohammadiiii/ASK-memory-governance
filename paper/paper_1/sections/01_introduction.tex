\section{Introduction}
\label{sec:intro}

A persistent-memory agent can turn one interpretation of a conversation into a
durable commitment. If the agent stores an ambiguous claim as fact, retains an
obsolete preference, or replaces a record without history, the error may affect
answers in later sessions. Memory systems commonly expose operations such as
add, update, delete, merge, or no-op \citep{packer2023memgpt,chhikara2025mem0,
yan2025memoryr1}. Those operations explain how a store can change. They do not,
by themselves, establish whether the available evidence warrants a durable
change.

Final-answer evaluation is insufficient for this question. A correct write can
still be followed by failed retrieval or generation, while an incorrect write
can be hidden by answer-time reasoning or accidental retrieval. A single
end-to-end score therefore cannot localize whether the failure occurred during
candidate extraction, target resolution, governance, state mutation,
retrieval, or answer generation. It also encourages several distinct events to
be treated as interchangeable: preserving a valid record, accepting a
compatible record, refusing an uncertain write, deleting a record, retrieving
nothing, and refusing to answer.

ASK places an explicit governance boundary before persistent mutation. Given a
state $M$, candidate update $u$, and attributable evidence $E$, a controller
proposes one of three actions. \keep{} does not invalidate the compared prior
record. \supersede{} makes a successor active while preserving the predecessor
and its lineage. \abstain{} refuses the proposed durable commitment because the
evidence is insufficient. The action is then applied by a transition mechanism,
not directly by the proposing model. This separation permits controllers and
storage adapters to vary while preserving a common decision and state contract.

ASK is not a three-class classifier. Its normative reference protocol specifies
typed candidates and records, evidence and configuration identity, transition
semantics, state and lineage invariants, replay scope, and immutable transition
events. The repository also contains evaluated implementations with narrower
runtime guarantees. The LongMemEval pipeline uses candidate extraction, target
selection, a transparent five-dimensional controller, transactional SQLite
supersession, active-only retrieval, historical-lineage lookup, and structured
decision logs. It does not call the generic reference validator or emit the
reference transition event on its live mutation path. We make this boundary
explicit because a tested specification and an integrated runtime are different
forms of evidence.

We evaluate ASK in layers. Executable conformance tests exercise the reference
transition contract. \mgpc{} directly tests evidence-sensitive write decisions
and their single-slot state consequences. \lme{} tests one longer pipeline in
which governed writes, retrieval, and answer generation interact, but it has no
gold action for each extracted candidate. The earlier \mgp{} pilot is retained
only as a construct-validity lesson: a conflict-type lookup predicts every
held-out label without reading the dialogue. The separate MGP-Natural track is
present as a quarantined feasibility seed and v0.2.2 construction software, but
it is not reported as an experiment because it has no independently annotated,
rights-cleared, frozen evaluation set.

The contributions supported by the repository are:
\begin{enumerate}[leftmargin=1.5em,topsep=2pt,itemsep=2pt]
\item ASK, a controller- and storage-independent write-governance protocol that
separates evidence assessment, action proposal, validated mutation, retrieval,
and downstream response.
\item A formal transition contract for state-preserving \keep,
lineage-preserving \supersede, and uncertainty-based \abstain, with executable
invariants and declared replay scope.
\item An implemented architecture comprising a reference protocol engine and a
separately evaluated LongMemEval runtime, together with an explicit account of
which audit guarantees each path actually realizes.
\item A layered evaluation methodology that reports action, state, lineage,
retrieval, answer, uncertainty, and asymmetric operational cost without
collapsing them into one score.
\item Complementary empirical evidence from \mgpc{} and \lme{}, including
component-cluster uncertainty, harm-specific error decomposition, exact
decision replay, and a documented failure of the earlier v2 diagnostic.
\end{enumerate}

We do not claim to have invented memory update operations, abstention, typed
memory, provenance, lineage, version history, belief revision, selective
prediction, or operation-level evaluation. The scientific claim concerns the
integrated governance contract, its separation from storage execution and
answer generation, and the measurements this separation enables. MGP-6 is one
controlled diagnostic for that claim. It is not the identity of the method or
the paper.
