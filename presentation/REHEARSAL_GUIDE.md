# Defense rehearsal guide

## Target

20–25 minutes for slides 1–20. Slides 21–31 are backup only.

## Pacing

- Slides 1–4: 4 minutes — establish the write-governance problem and the narrow research gap.
- Slides 5–10: 7 minutes — define the actions, architecture, controller, lineage, diagnostic, and protocol.
- Slides 11–15: 7 minutes — completed MGP-6 results, ablations, adapters, and annotation evidence.
- Slides 16–19: 5 minutes — negative downstream evidence, SSP analysis, errors, and limitations.
- Slide 20: 1–2 minutes — answer the research question and close.

## Rehearsal checks

1. Say “author-designed diagnostic,” never “community benchmark,” for MGP-6.
2. Say “one independent annotator,” never “multi-human agreement.”
3. Describe 77.2% only as an ineligible failure-replay construction.
4. State that final-1.1 is externally_pending and has no predictions.
5. For adapters, state both NOOP mappings and call them harness-dependent bounds.
6. Do not claim invention or primacy for abstention, versioning, provenance, lineage, update actions, or memory governance.
7. Practice the transition from slide 15 to 16: completed decision evidence ends; downstream evidence is explicitly incomplete.
8. Keep backup slides closed unless a question asks for exact formulas, tests, mappings, novelty, ethics, or code structure.

## Likely opening

“Long-term memory systems are usually evaluated by what they retrieve. This thesis asks an earlier question: what should the system have committed as memory in the first place?”

## Likely closing

“The verified contribution is a measurable, auditable write boundary and a layered evaluation showing why decision, state, and answer quality must be separated. A homogeneous downstream run remains the next external action.”
